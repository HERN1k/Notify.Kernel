## 🏗 Архітектурна структура проєкту

```text
Notify.Kernel/
├── Core/
│   ├── Abstractions/
│   │   ├── INotificationProvider.cs     # Абстракція для провайдерів (SMS, Viber, Email)
│   │   └── IWorkflowEngine.cs           # Інтерфейс виконуючого рушія
│   └── Models/
│       ├── CustomerDto.cs               # DTO сутності, сумісної з MySQL
│       ├── WorkflowConfig.cs            # Модель конфігурації сценарію
│       └── NotificationPayload.cs       # Модель корисного навантаження сповіщення
├── Infrastructure/
│   ├── Data/
│   │   └── CustomerRepository.cs        # Доступ до даних через Dapper / MySqlConnector
│   ├── Providers/
│   │   ├── SmsClubProvider.cs           # Провайдер SMS (SmsClub API)
│   │   ├── ViberSmsClubProvider.cs      # Провайдер Viber (SmsClub API)
│   │   └── EsputnikProvider.cs          # Провайдер Email (eSputnik API)
│   └── Serialization/
│       └── SourceGenerationContext.cs   # System.Text.Json Source Generator для Native AOT
├── Services/
│   └── WorkflowEngine.cs                # Оркестратор виконання сценаріїв та кроків
├── Program.cs                           # Точка входу, CLI-парсер, Bootstrap DI, Exit Codes
└── Notify.csproj
```

## 2. Підготовка та конфігурація проєкту (.NET Native AOT)

- [x] **Ініціалізація консольного проєкту** — `dotnet new console -n Notify.Kernel`
- [x] **Активація компіляції Native AOT** — додано `<PublishAot>true</PublishAot>` у `.csproj`
- [x] **Вибір та перевірка AOT-сумісних залежностей**

| Пакет | Призначення |
| --- | --- |
| `Microsoft.Extensions.Configuration` | Зчитування `appsettings.json` та змінних середовища |
| `VYaml` | Розбір YAML з перевіркою сумісності зі Static Code Generation |
| `MySqlConnector` | Асинхронний AOT-сумісний драйвер MySQL |
| `Dapper` | Мікро-ORM (`DefaultTypeMap.MatchNamesWithUnderscores = true`, без динамічної рефлексії) |
| `System.Net.Http.Json` | HTTP-клієнти на базі генераторів коду |
| `Microsoft.Extensions.Logging` | Консольне та файлове логування |

## 🚦 Матриця кодів завершення (Exit Codes)

| Код | Опис стану | Дія на стороні PHP |
| :---: | --- | --- |
| `0` | ✅ **Success** — воркфлоу успішно виконано | Обробити результат та завершити скрипт успішно |
| `1` | ⚠️ **Invalid Arguments** — некоректні або відсутні CLI-аргументи | Записати в лог помилку виклику та аргументів |
| `2` | ⚠️ **Configuration Error** — помилка читання або синтаксису конфігу | Сповістити розробників, зупинити виконання |
| `3` | 🔌 **Database Error** — помилка з'єднання з БД або виконання SQL | Відправити завдання на повторну спробу (Retry) |
| `4` | 📡 **Provider Error** — помилка зовнішніх API (SmsClub, eSputnik тощо) | Зафіксувати збій розсилки, відправити у fallback/DLQ |
| `5` | ⚠️ **Invalid Operation** — некоректна дія для поточного стану системи | Записати в лог помилку бізнес-логіки |
| `6` | ⏹ **Operation Canceled** — операцію скасовано (таймаут або скасування таски) | Зафіксувати переривання, не повторювати виклик |
| `7` | 📂 **File Not Found** — не знайдено необхідний файл (шаблон, файл даних) | Перевірити існування файлів за шляхом |
| `8` | ⚠️ **Invalid Config** — конфіг прочитано, але значення не пройшли валідацію | Логувати помилку схем/параметрів конфігурації |
| `99` | 🔥 **Unhandled Exception** — непередбачена критична помилка | Критичний лог у системну чергу, сповістити dev-команду |
